The short version

pi 的核心赌注：把 harness 做薄

“Harness” 是包在大模型外面的那层工程：拼上下文、发请求、执行工具、存会话、渲染界面。大多数产品的做法是把策略写死在 harness 里；pi 反过来，把策略尽量上移为扩展、技能、提示模板与设置，核心只保留一个足够通用的循环和一套清晰的事件与类型契约。

这使得 pi 的源码非常适合作为“agent 系统如何工作”的教材：分层干净，边界类型化，关键决策都有注释。读它，比读一个把所有东西揉进一个 agent.ts 的项目更能建立可迁移的心智模型。

Surface

pi-coding-agent · modes

交互 TUI、print/JSON、RPC、SDK 四种外壳。共享同一个 AgentSession；差别只在输入输出。

Harness

AgentSession · SessionManager

装配系统提示、工具、模型与扩展；把会话落成可分支的 JSONL 树；负责压缩、重试、队列。

Runtime

pi-agent-core

纯 agent loop：流式 assistant、工具调用批处理、steering / follow-up、生命周期事件。

Protocol

pi-ai · providers

统一 Model / Context / Message / AssistantMessageEvent；把十几种 provider 的差异关在适配器里。
